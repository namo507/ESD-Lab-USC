## Corrections to my own work, found by the suites I wrote

Recorded because they are the kind of bug that survives review:

- The **corpus PHI guard** initially ran `is_phi_or_raw_request` over documentation
  prose. That function matches the *shape of a request* ("list the participants"),
  not PHI content, and it dropped 361 chunks of the lab's own docs while finding
  no actual PHI. The corpus now uses the two *content* guards
  (`_EXPLICIT_IDENTIFIER_RE`, `_DIRECT_PHI_RE`) plus email/phone; the request
  guards stay active on the query path. Dropped chunks fell to 187 with precision
  verified in both directions.
- A **corrupt index raised** `sqlite3.DatabaseError` instead of degrading, because
  `sqlite3.connect()` validates the header lazily. Found by the chaos suite; the
  index is now probed on open and a corrupt one returns no results.
- The **domain router** ordered topic before question-shape, sending "how many
  instruments does NANO have" to the clinical specialist and "what is the
  relationship between NANO and NICO" to the deterministic tier. Found by the eval
  fixtures; the predicate order is now explicit and documented.
- Marker matching used bare substrings, so `"are the"` matched inside
  `"comp**are the** ACTION and IPSA designs"`. Now word-boundary anchored.
- Four of my own **eval fixtures asserted the wrong expectation** and were
  corrected against observed behaviour, not the other way round.

  chat path.

  brief, and the platform is fully functional without it.
- **The reranker** (`bge-reranker-v2-m3`) is not wired. Retrieval fuses sparse and
  dense by RRF and stops there.
